## Project Name

AstroVital

## High-Level Summary

AstroVital is an installable web app (PWA) and Android app that shows an astronaut's wellness status across three mission stages: before the trip, during the stay and after returning. A 3D body model highlights attention zones in red and stable indicators in green, depending on the situation evaluated (microgravity, radiation, cabin CO2, spacewalks, solar storms). The app queries live solar flare data for the last 30 days and uses open space-biology and radiation datasets to give context about bone, muscle, heart and radiation risk. Everything is stored on the device and the app works offline. Vital signs are simulated and clearly labeled as such, and the app is not a medical device. It matters because long-duration missions need crew and ground teams to understand, visually and simply, how health risks change over time and with space weather.

## Detailed Project Description

**What it does.** AstroVital is a crew-centered wellness dashboard. The Home tab shows a 3D body model, a greeting, three mission-stage cards (before, during, after), the status of the data sources and a mood log. The user can run a "scan" for a stage and pick one of 14 demo situations; the app saves a record with date, simulated vital signs and highlighted zones, and shows them on the 3D model. The Vitals tab shows simulated readings that refresh every 4 seconds and "accumulated mission effects" computed by an experimental model. History and Profile keep records on the device only.

**How it works.**
1. A JSON input contract (`data/risk_inputs.json`) is generated by a Python script (`data/ingest/fetch_nasa_data.py`).
2. Solar flares of the last 30 days are fetched live when the app opens. If the connection fails, the last valid response is used; if none exists, the app shows "no data" and never assumes zero.
3. An experimental risk model (`model/risk.js`) returns 0-1 indices for spine, femur, leg muscle and heart, with a reason and a source for each.
4. Three.js renders the 3D model. Zones (heart, lungs, brain, spine, femurs, body) are matched by node name in the model file.

**Data honesty.** Mission day, radiation in uSv/h and cabin CO2 are provisional placeholders from the team's data contract and are labeled as such. The DosTel reference (28.303083 uGy/h, 2023-01-01) is a historical absorbed dose and is not converted to uSv/h. Red zones are educational references, not injuries or personal doses.

**Benefits and goal.** An educational tool to raise awareness of human health in space, and an interface prototype that could later connect to real telemetry (environmental data, radiation data, wearable sensors).

**Tools used.** HTML, CSS and JavaScript (ES modules), Three.js 0.170 (local copy), PWA (manifest and service worker), Python 3 with `requests` for data ingestion, Kotlin for the native Android app, GitHub Pages for hosting.

**Limitations.** No real sensors; vital signs are simulated; the risk model is experimental and gives no diagnosis or clinical prognosis.
